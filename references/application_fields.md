# 申请表信息字段

以下字段按软件著作权登记申请表的字段顺序与字段名列出：

1. 软件全称
2. 版本号
3. 软件分类（应用软件/嵌入式软件/中间件/系统软件/其他）
4. 开发完成日期（YYYY-MM-DD）
5. 开发方式（单独开发/合作开发/委托开发/下达任务开发）
6. 软件说明（原创 / 修改（含翻译软件、合成软件））
7. 发表状态（已发表/未发表）
8. 首次发表日期（已发表时填写，YYYY-MM-DD）
9. 著作权人（复合字段：国家/省市/类型[自然人/法人]/姓名/证件类型/证件号）
10. 权利范围（全部权利/部分权利）
11. 权利取得方式（原始取得/继受取得）
12. 开发的硬件环境（≤50字符）
13. 运行的硬件环境（≤50字符）
14. 开发该软件的操作系统（≤50字符）
15. 软件开发环境 / 开发工具（≤50字符）
16. 该软件的运行平台 / 操作系统（≤50字符）
17. 软件运行支撑环境 / 支持软件（≤50字符）
18. 编程语言（预设按钮选择 + 自定义输入≤120字符）
19. 源程序量（纯数字，单位行，指全部源程序总行数）
20. 开发目的（≤50字符，宏观说明真实业务场景）
21. 面向领域 / 行业（≤50字符）
22. 软件的主要功能（500~1300字）
23. 软件的技术特点（多选标签 + 文本描述≤100字符；标签：APP/游戏软件/教育软件/金融软件/医疗软件/地理信息软件/云计算软件/信息安全软件/大数据软件/人工智能软件/VR软件/5G软件/小程序/物联网软件/智慧城市软件，都不符合时可不选）
24. 页数（代码鉴别材料实际页数）

## 字段来源与填写口径

- 软件全称、版本号、开发完成日期：由用户确认。
- 软件全称必须显式确认；正式资料文件名、代码 Word 页眉、用户手册标题与正文中的软件名称，均以申请表信息中的「软件全称」为准。
- 版本号必须显式确认；项目配置中的版本号小于 V1.0 时，须提醒用户首次登记通常填写 V1.0，并由用户确认填写 V1.0 或项目当前版本号。
- 软件分类：默认选择「应用软件」。
- 开发完成日期与首次发表日期：必须使用 YYYY-MM-DD 格式。
- 开发方式：默认为「单独开发」，多人合作项目选择「合作开发」。
- 软件说明：本次默认「原创」。
- 发表状态：本次默认「未发表」，首次发表日期留空；如项目实际已发表，须修改并填写首次发表日期。
- 著作权人、权利范围、权利取得方式：本次分别默认「南京大学」「全部权利」「原始取得」；正式生成前仍须核对申报事实。
- 编程语言、源程序量、功能模块、技术特点：依据项目分析生成。编程语言按申请表支持的预设选项与自定义输入填写（≤120字符），预设选项包括 Assembly language、C、C#、C++、Delphi/Object Pascal、Go、HTML、Java、JavaScript、MATLAB、Objective-C、PHP、PL/SQL、Perl、Python、R、Ruby、SQL、Swift、Visual Basic、Visual Basic .Net。
- 源程序量：仅填写纯数字（不含「行」字），根据项目全量源码统计；项目分析未能取得全量统计时保留待确认，不得用抽取材料行数代替。
- 软件开发环境 / 开发工具：本次填写 `Visual Studio Code`，不填写技术栈名称。
- 开发该软件的操作系统：本次填写 `macOS 12.7.6`。
- 该软件的运行平台 / 操作系统：本次以 `VS Code 1.80+` 为基础；其他运行平台须由实际代码环境支撑。
- 软件运行支撑环境 / 支持软件：本次以 `Python 3.10+、VS Code、SQLite、Chroma` 为基础；其他依赖从项目配置补充，总长≤50字符。
- 开发的硬件环境：本次填写 `Apple Silicon CPU 10核、arm64、内存32GB、硬盘约926GB`。
- 运行的硬件环境：本次填写 `同开发环境`。
- 开发目的：≤50字符，从宏观业务场景说明软件用途，例如面向测试教学、科研实验与工程验证等真实场景，不能只写软件名称。
- 面向领域 / 行业：≤50字符。
- 软件的主要功能：500~1300字，详细描述软件核心功能，篇幅不少于 500 字。
- 软件的技术特点：多选标签（APP/游戏软件等）+ 文本描述≤100字符；在限制内写清真实技术机制、处理方式和差异化特点，标签均不符合时可不选。

## 一致性要求

- 软件全称与版本号必须与代码材料、用户手册一致。
- 正式代码 Word 页眉的软件名称必须与申请表信息中的「软件全称」一致，生成 Word 时以申请表的软件全称为准。
- 正式代码 Word 页眉的版本号必须与申请表信息中的「版本号」一致，生成 Word 时以申请表的版本号为准。
- 主要功能必须来自当前项目，不得沿用范本中的旧项目描述。
- `待用户确认` 字段在正式输出前应尽量替换为确认值；若仍然存在，必须写入生成报告。
- 校验脚本对「著作权人」与「软件全称」两个字段另设占位检测，命中「示例」「XX」「Demo」「ACME」一类词即判为失败。若该词确属软件的正当名称，在工作目录下建立 `主体名称确认.json`，将 `identity_names_confirmed` 置为真并在 `fields` 中逐字记录该字段的取值，校验即转为警告并注明依据。取值与申请表不一致时豁免不生效，以防改名后旧确认继续放行。
