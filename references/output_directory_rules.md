# 输出目录与材料归档规范

本规范适用于软著材料生成、截图整理和交付验收的全部阶段。在创建或写入任何文件前，须先确定目标项目根目录，并以该目录为基准解析以下相对路径。

## 固定根目录

正式执行时，所有材料与中间产物统一写入：

```text
<项目根目录>/软件著作权申请资料/
```

「项目根目录」指当前申请对应软件项目的根目录，不是 Skill 目录、用户主目录或任意终端当前目录。使用脚本的相对默认路径前，须先进入目标项目根目录；也可以显式传入该根目录下的完整输出路径。

只有测试 Skill 自身时，才允许通过命令参数把输出显式指向隔离的临时目录。测试产物不得混入任何真实项目的申请资料。

## 归类规则

- `analysis/` 只保存项目扫描和结构化分析结果，不放业务成稿、申请材料或浏览器记录。
- `草稿/` 保存所有尚需模型研判、用户补全或确认的内容，包括业务理解、申请信息、代码抽取草稿和用户手册草稿。
- `操作视频/` 只保存视频抽帧产物和帧清单。外部原始视频保留在原位置，在 `视频证据.md/json` 中记录来源路径，不强制复制大文件。
- `用户截图/` 保存用户提供的原始图片，尽量保持原文件不变；`截图/` 保存按手册模块整理后的图片。
- `正式资料/` 是正式交付材料的唯一目录。四类 Word 文档及对应生成报告在此归档；草稿、确认记录和原始视频不得混入。
- 根目录只保存环境检查、根级阶段确认/确认记录文件和总校验报告。业务阶段自身的确认状态随对应草稿 JSON 保存在 `草稿/`。

## 命名规则

- 正式材料的文件名以用户已确认的「软件全称」和「版本号」为准，沿用生成脚本定义的名称；不得用临时简称覆盖已确认字段。
- 正式文档统一使用 `.docx`，不生成 PDF、TXT 或其他交付格式。
- 用户手册截图按功能模块和页面含义命名，例如 `项目管理-列表页.png`；用户原始截图不因整理而覆盖，可复制到 `截图/` 后另行命名。
- 视频帧沿用脚本生成的 `frame_0001.png` 递增格式，不按主观功能重命名原始帧。

## 禁止事项

- 不得把正式运行产物默认写到临时目录，也不得把 Skill 测试产物写入真实申请目录。
- 不得把草稿、分析文件或原始视频放入 `正式资料/`。
- 不得直接编辑或覆盖 `用户截图/` 中的原始图片；整理结果另存到 `截图/`。
- 不得复制外部原始视频作为默认动作；只有用户明确要求归档副本时才复制。
- 不得因为采用新规范而自动移动、删除或重命名既有申请材料。

## 旧项目兼容原则

已有项目可能把文件放在根目录或使用 `操作视频2/` 等历史目录。遇到这些情况：

1. 保留原文件和原路径，不自动整理、迁移、删除或覆盖。
2. 读取旧文件时允许使用其现有路径；自本次继续产生的新文件开始遵守本规范。
3. 若旧路径仍被当前确认点或脚本引用，优先保持兼容，不得为目录整洁而破坏可继续执行性。
4. 在最终交接中注明仍在使用的历史路径，避免后续人员误认。
5. 只有用户明确要求迁移并确认目标范围时，才另行执行迁移；迁移前后都要核对文件清单和内容。
